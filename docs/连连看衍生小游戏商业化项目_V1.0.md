# 连连看衍生小游戏商业化项目

## 整体设计与落地实施方案 V1.0

核心目标：用成熟玩法降低理解成本，用差异化情绪与题材制造进入理由，
以低成本MVP和真实收入数据筛选可规模化的Winner。

适用主体：现有“XX技术有限公司”（法人：本人）

版本日期：2026年10月27日

## AI Agent 开发投喂约束

> 本节用于后续开发、产品和营销 Agent 读取。除非项目负责人明确修改，以下约束视为 V1.0 的默认决策边界。

1. **项目目标不是开发一款连连看，而是建立可复用的低认知成本 Hybrid Casual 游戏实验平台。** 第一代 Core Gameplay 为连连看/配对消除。
2. **盈利优先于功能完整度。** 所有设计最终回到 `LTV > CAC + 边际运营成本`；播放量、下载量、点赞量不是最终成功指标。
3. **首轮产品优先级：B 整理解压 > A 快爽泄压 > C 爽文剧情。** A承担商业效率对照，B验证完成感与留存，C验证高LTV和未来IAP潜力。
4. **第一阶段以 IAA 为主。** 未出现 Winner 前，不为IAP提前承担版号、经营性ICP和重内容生产成本。
5. **Core 必须高度复用，内容必须配置化。** 关卡、Icon、NPC、剧情、广告点、Timer、Combo、清理/剧情模块都应尽量通过配置而不是硬编码实现。
6. **禁止无数据支撑的世界观膨胀。** 不做大世界、复杂农场模拟、重装备、PVP、公会、复杂经济系统、十几小时剧情或昂贵IP。
7. **Meta 只能服务核心玩法。** NPC、清理、收集、装修、剧情等模块的作用是提高“再玩一局”的意愿，而不是取代连连看成为新的重系统。
8. **玩法必须低认知成本，核心操作3秒可理解。** 优先适配手机竖屏、碎片时间、单手或低操作压力场景。
9. **产品和营销同时设计。** 每个MVP必须明确 Product Hook、Emotion Hook、Content Hook、Discussion Hook。
10. **从第一版开始埋点。** A/B/C共用统一事件字典，确保横向比较；禁止上线后补核心埋点。
11. **两轮红灯原则。** 同一产品连续两轮关键指标仍为红灯，默认 Kill；历史投入、个人偏好和题材感情不能成为继续投入的理由。
12. **Winner 才获得复杂度预算。** 只有当真实留存、广告收入、CAC/LTV出现明确正向信号后，才进入IAP、经营性ICP、版号、更大内容量和规模买量。

# 执行摘要
本项目不是“做一款连连看”，而是建立一个以连连看/配对消除为第一代Core Gameplay的低认知成本休闲游戏实验平台。玩法采用大众已经被教育过的成熟形式，减少用户学习成本；产品差异化来自情绪场景、Meta循环、题材包装和变现结构。

2026年上半年，中国小程序移动游戏实际销售收入316.57亿元，同比增长36.01%；其中内购收入211.37亿元，占66.8%，广告变现105.20亿元，占33.2%。微信小游戏大会披露，平台MAU超过5亿，IAA MAU超过4亿，年流水超过100万元的IAA产品超过1400款。休闲IAA用户中女性约占60%，且人均每月体验约7.5款小游戏。这说明市场既有规模，也天然适合“快速迭代、多产品赛马”的策略。[R1][R2]

>
> 用最成熟的玩法降低理解成本，用最鲜明的情绪和题材制造进入理由；先用IAA验证用户价值，用统一底座快速赛马，只为能形成正向单位经济模型的Winner继续重投入。

# 0. 商业模型与投资边界
## 0.1 商业定义
项目内部定义建议为“低认知成本 Hybrid Casual 游戏实验平台”。连连看并非品牌定位，而是第一套可复用的Core Gameplay。真正需要沉淀的是四层资产：核心玩法引擎、Meta模块、商业化模块、增长与数据模块。

| **资产层**    | **首版能力**                                                     | **为什么重要**                       |
|---------------|------------------------------------------------------------------|--------------------------------------|
| Core Gameplay | 配对判定、路径规则、死局、洗牌、提示、倒计时开关、连击、特殊棋子 | 决定开发复用率                       |
| Meta          | 清理、收藏、轻成长、剧情、装修/经营的可插拔模块                  | 决定留存与题材扩展                   |
| Commercial    | 广告、复活、提示、体力、礼包、免广告、远程参数                   | 决定变现效率                         |
| Growth & Data | 埋点、AB测试、渠道归因、素材标签、用户分层                       | 决定是否能从“博概率”升级为“数据赛马” |

## 0.2 两阶段变现策略
第一阶段以IAA为主，优先验证真实用户是否愿意为了继续游戏付出“30秒注意力成本”。可测试的广告节点包括复活、额外时间、提示、洗牌、补体力、双倍奖励。第二阶段只给胜出产品增加IAP：3元、6元、9.9元等低决策成本的小额付费，用于免广告、无限体力、工具包、剧情/场景包等。

> **为什么不首发就做IAP**
>
> IAP会把项目提前带入版号、经营性ICP、出版单位合作、防沉迷材料和更复杂的支付合规链条。对尚未验证留存和LTV的产品来说，这是一笔不必要的沉没成本。

## 0.3 单位经济模型
项目最终只接受一个商业判断：用户全生命周期价值LTV必须高于获客成本CAC和边际运营成本。播放量、下载量、点赞量只能解释流量，不直接代表商业成功。

| **指标**   | **定义**                        | **经营用途**                     |
|------------|---------------------------------|----------------------------------|
| CAC        | 获得1名有效新增用户所需投放费用 | 判断买量是否可放大               |
| 广告ARPDAU | 日活用户平均广告收入            | 判断IAA效率                      |
| LTV        | 用户生命周期累计广告+内购收入   | 决定最多可以花多少钱获客         |
| LTV/CAC    | 单位经济核心比值                | <1长期不可放大；>1后再考虑规模 |
| D1 / D7    | 次日/7日留存                    | 判断产品是否有重复使用价值       |

## 0.4 第一阶段投资红线
由于已有公司主体，第一阶段不再包含公司设立成本。建议在找到明确Winner之前，项目总现金投入原则上不超过3万元；其中基础设施与合规准备尽可能控制在5,000元以内，把主要可变预算留给素材和小流量测试。

| **预算项**                | **建议区间**    | **说明**                                       |
|---------------------------|-----------------|------------------------------------------------|
| 现有公司工商/基础合规调整 | 0–1,500元       | 自行线上办理通常成本低；如找代理则产生服务费   |
| 微信企业认证              | 约300元/年/账号 | 企业主体当前常见认证审核服务费口径；以后台为准 |
| 域名、SSL、云资源         | 300–1,500元     | MVP阶段可用轻量云/云开发，避免过度建设         |
| 软著/权属材料             | 0–1,500元/款    | 直接申请公共服务成本可很低；代理或加急另计     |
| AI美术/音效/素材工具      | 1,000–3,000元   | 以月订阅和少量素材采购为主                     |
| 三款MVP小流量测试         | 9,000–15,000元  | 建议每款3,000–5,000元                          |
| 预备金                    | 2,000–5,000元   | 审核修改、外部服务、素材补充                   |

以上为内部预算假设，不是政府统一收费标准。尤其版号、出版合作、增值电信资质等后续费用，需在Winner出现后单独询价。

# 1. 产品设计
## 1.1 产品定位
第一阶段从“银发经济”中提炼需求，但不把用户限定为高龄人群。真正聚焦的是一种使用状态：不想学习复杂规则、不想被持续催促、希望在碎片时间获得轻松、完成感或情绪释放。内部可称为“低认知成本休闲需求”。

> **核心用户洞察**
>
> “我现在不想动脑子，但我想获得一点爽感。” 这个状态既属于40–60岁的熟龄用户，也属于下班后疲惫的20–40岁打工人。

## 1.2 共同产品原则
- 玩法大众，产品不能大众：不能让用户第一眼只看到“又一个连连看”。

- 不是创新规则，而是创新“为什么要玩”：清理、逃离、逆袭、建设、收集都可以是进入理由。

- 慢节奏不等于弱反馈：砍掉倒计时后，必须用完成感、收集、成长、探索和建设补回爽感。

- Meta服务于核心玩法：NPC、农场、装修和剧情只负责让用户更愿意再玩一局，不做大世界。

- 产品Hook和营销Hook同时设计：每个MVP立项时必须能用一句话说明差异和冲突。

- 核心玩法3秒看懂：买量素材和小游戏首屏都必须降低认知门槛。

## 1.3 用户画像（按心理状态而非年龄）
| **用户群**          | **典型场景**                 | **真正需要的东西**                   | **高价值行为**                       |
|---------------------|------------------------------|--------------------------------------|--------------------------------------|
| 打工人泄压型        | 午休、通勤、下班、睡前       | 快速发泄、临界过关、吐槽共鸣         | 失败后主动复活、连续多局             |
| 慢休闲/整理解压型   | 看短视频后的碎片时间、睡前   | 视觉秩序、清空、Before/After、低压力 | 长Session、主动提示/工具广告         |
| 剧情/成长型女性用户 | 晚间连续游玩、追爽文短剧场景 | 逆袭、经营、角色关系、装修和身份成长 | 高复访、为继续剧情付出广告或小额付费 |

## 1.4 MVP A：快爽泄压型
### 建议概念：《逃离办公室》 / 《末班地铁》
A线保留传统连连看的时间压力、Combo和临界过关，用打工人场景增强情绪共鸣。它不是最创新的一条线，而是商业效率对照组，用来测“压力—失败—不甘心—广告”的最短变现路径。

| **模块**   | **V1设计**                                                    |
|------------|---------------------------------------------------------------|
| 核心循环   | 60–90秒配对消除 → Combo/清屏 → 过关/失败 → 继续下一“工作事件” |
| 题材       | 周五17:59改需求、PPT返工、甲方催命、末班地铁、加班逃离        |
| 反馈       | 夸张音效、屏幕震动、文件爆炸、任务清空、临界过关              |
| 广告点     | +30秒、原地复活、提示、洗牌、双倍奖励                         |
| 营销Hook   | “周五17:59，老板说有个简单需求。” / “只剩5秒，能不能下班？”   |
| 第一版范围 | 20–30关、2个场景、3种特殊棋子，不做复杂剧情                   |

## 1.5 MVP B：整理解压型（优先级最高）
### 建议概念：《清理大师》
B线把清洁、收纳、整理、修复视频中的被动爽感转化为主动操作。玩家从“清理小白”成长为“清理大师”，NPC持续发来新的清理任务；核心玩法仍然是连连看，但消除对象与场景直接发生关系。

| **模块**   | **V1设计**                                                             |
|------------|------------------------------------------------------------------------|
| 第一关     | 老王请你清理农场鸡圈。鸡、鸡蛋、饲料、水桶、草堆、工具形成配对棋盘     |
| 视觉爽点   | 脏→净、乱→齐、堵→通、堆积→清空、破旧→修复；最后强制呈现Before/After    |
| 成长       | 清理等级、3类工具、少量纪念物收藏；不做复杂经营                        |
| 内容扩展   | 猪圈、厨房、地毯、宠物店、车库、海滩、旧公寓、阁楼、花园等可无限加场景 |
| 广告点     | 提示、洗牌、特殊工具、隐藏污渍、三倍奖励、额外场景奖励                 |
| 营销Hook   | “强迫症千万别点进来。” / “别人游戏都在催你，这个只想让你慢慢收拾。”    |
| 第一版范围 | 15–20个清理场景，3类场景主题，6–10个NPC                                |

> **B线最重要的产品判断**
>
> 慢节奏不是“没有爽感”，而是把时间压力爽感替换为视觉完成感。B线如果成立，最有机会同时覆盖熟龄、女性和打工人，并且天然适合短视频素材生产。

## 1.6 MVP C：爽文剧情型（高LTV实验）
### 建议概念：《重生后我开了一家酒楼》
C线不以“探索题材是否有趣”为第一目标，而以“高价值用户是否愿意长期投入”为第一目标。当前微信小游戏数据显示，IAP大盘用户已超过3亿，模拟经营近一年增速约210%，二合赛道仍保持70%以上增长；女性付费用户的增长也使“女性爽文+轻经营+低门槛Puzzle”成为更适合本项目的高LTV实验方向。[R2]

| **模块**       | **V1设计**                                                        |
|----------------|-------------------------------------------------------------------|
| 剧情钩子       | 上一世被丈夫/合伙人算计，重生回十年前，决定救回快倒闭的家业       |
| 核心循环       | 连连看配食材/完成订单 → 赚钱 → 修复酒楼 → 解锁剧情 → 下一关       |
| 爽点           | 受辱→翻身→搞钱→建设→打脸→身份提升                                 |
| 轻Meta         | 3个装修区域、少量NPC、进度条式经营；不做真实模拟经营经济系统      |
| 广告/IAP代理点 | 体力、继续剧情、特殊订单、加速修复；后续可测试3/6/9.9元权益       |
| 换皮能力       | 穿越茶楼、冷宫逆袭、花店、仙门、鉴宝店等，仅换文本/立绘/背景/Icon |
| 第一版范围     | 3章、30–45分钟核心内容、6–8个主要NPC                              |

|-----------------------|--------------------------------------|------------------------------------|
| Vita Mahjong          | 低压力、大图标、慢节奏配对体验       | 不贴“老年游戏”标签，不照搬麻将视觉 |
| 打个螺丝/解压打毛线等 | 3秒看懂、整理/完成感、素材可视化     | 不只靠一次性噱头                   |
| 梦幻消除战            | 爽文剧情+经营+基础休闲玩法的分工     | 不堆几十套Meta系统                 |
| 我的花园世界/浪漫餐厅 | 女性审美、建设、长期目标             | 不做完整农场/餐厅模拟器            |
| Royal Match           | 基础Puzzle的高反馈品质               | 不走高成本精品化路线               |
| Gossip Harbor         | 核心Puzzle负责资源，剧情负责长期牵引 | 不承担大规模手工剧情成本           |

# 2. 完整实施方案
## 2.1 现有“XX技术有限公司”是否可以直接用？
结论：大概率应该直接复用现有公司，不建议新设公司。你本人已经是法定代表人，这对微信企业认证、备案真实性核验、银行/税务配合都更方便。只有在公司存在外资股东、经营异常、历史重大合规问题、注册资本/股权结构明显不适合未来申请增值电信资质，或你希望把游戏业务做风险隔离时，才值得新设主体。

### 2.1.1 第一步：先做“公司体检”
| **检查项** | **你现在要做的动作**                                   | **判断标准**                                                                   |
|------------|--------------------------------------------------------|--------------------------------------------------------------------------------|
| 企业状态   | 在国家企业信用信息公示系统查询公司状态、年报、异常名录 | 必须为正常存续，尽量无经营异常/严重违法                                        |
| 股东结构   | 查看营业执照/章程/工商档案                             | 未来版号路径优先保持内资；如存在外资，先咨询出版和电信许可专业意见             |
| 注册资本   | 看营业执照/章程                                        | 若未来自己做游戏运营机构并申请省内ICP，建议至少具备100万元注册资本条件[R7]   |
| 实缴期限   | 看章程和国家企业信用信息公示                           | 不要为满足资质随意大幅增资；新增认缴资本原则上自变更登记之日起5年内缴足[R8]  |
| 经营范围   | 看营业执照                                             | 先确认是否已有“软件开发/动漫游戏开发/数字文化创意软件开发”等；缺失再做最小变更 |
| 税务状态   | 电子税务局/财务确认                                    | 无欠税、非正常户；后续广告结算能正常开票/记账                                  |
| 银行账户   | 确认基本户可用                                         | 平台结算、认证和供应商合同最好都走公司账户                                     |

> **不要为了“以后可能办ICP”立刻把注册资本改得很高**
>
> 增值电信许可省内经营常见法定最低注册资本为100万元；但2024年以后新增认缴资本存在五年缴足要求。建议只补到满足实际许可和经营需要的水平，不做夸张注册资本。[R7][R8]

### 2.1.2 经营范围怎么处理：建议分两阶段
经营范围采用市场监管总局规范表述，具体可选项以公司注册地市场监管登记系统为准。对第一阶段IAA验证，不建议一口气把所有许可项目都加满；先补足游戏研发相关一般项目，未来确定要申请经营性ICP/版号时再加入许可项目并办证。经营范围本身不是许可证，写入“互联网信息服务”或“第二类增值电信业务”不代表已经获得许可。

| **阶段**          | **建议关注的经营范围表述**                                                                               | **操作建议**                                                                        |
|-------------------|----------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------|
| 阶段1：IAA/MVP    | 软件开发；动漫游戏开发；数字文化创意软件开发；技术服务、技术开发、技术咨询、技术交流、技术转让、技术推广 | 如果现有范围已经覆盖软件/技术开发，可先不变；缺“动漫游戏开发”可在一次工商变更中补齐 |
| 阶段2：IAP/版号前 | 互联网信息服务；第二类增值电信业务（均为许可项目，具体以本地规范目录为准）                               | 确定Winner后再变更，并同步申请实际许可证；不要只改营业执照不办许可                  |
| 可选商业范围      | 广告设计、代理；广告制作；广告发布；数字内容制作服务（不含出版发行）                                     | 只有实际业务需要时再加，不作为首款小游戏上线的硬前置                                |

### 2.1.3 什么时候必须考虑注册资本100万元
国家新闻出版署国产网络游戏审批条件明确要求“游戏运营机构须具有ICP证”。而通信管理部门对省内增值电信业务经营许可的通用条件包括：依法设立的公司、与业务相适应的资金和人员，以及省内经营时注册资本最低100万元人民币等要求。[R3][R7] 因此，如果后续由你的公司作为版号中的“运营机构”，注册资本不足100万元时，应在申请ICP前解决。

### 2.1.4 公司主体和知识产权必须从第一天对齐
- 所有小游戏AppID由公司自己注册并由你或公司指定管理员掌控，不让外包商持有主账号。

- Git仓库、云账号、域名、微信后台、广告后台、素材源文件均使用公司可控邮箱/手机号。

- 程序员、美术、编剧、配音如为外包，合同明确“成果著作权/可转让权利归公司”，并约定第三方素材合法来源。

- 软件著作权申请人优先统一为公司；游戏名称、软著名称、未来版号申报名称尽量提前保持一致。

- AI生成素材保留生成记录、提示词、原始文件和人工修改记录；避免直接模仿明确影视/IP角色或商标形象。

## 2.2 微信小游戏账号与平台基础能力
### 2.2.1 账号建议
第一款正式MVP建议直接以现有公司作为企业主体注册小游戏账号。每款独立小游戏都应拥有自己的AppID和版本管理空间；第一阶段不要一次注册十几个账号，先注册1个跑通从认证、备案、提审、发布、流量主到结算的全链路，再复制到B/C。

| **动作**                   | **实操建议**                                                                                                   | **负责人**    |
|----------------------------|----------------------------------------------------------------------------------------------------------------|---------------|
| 注册微信公众平台小游戏账号 | 使用公司长期可控邮箱；主体选企业；类目按实际休闲益智内容选择                                                   | 你/公司管理员 |
| 企业认证                   | 准备营业执照、法定代表人/认证联系人信息、对公账户等；企业认证当前常见费用约300元/次，以平台实际页面为准[R10] | 你            |
| 管理员与权限               | 主管理员不使用外包个人账号；开发者只给开发权限，不给可变更主体的最高权限                                       | 你            |
| 获取AppID                  | 统一登记到公司资产台账                                                                                         | 产品/技术     |
| 适龄提示/内容资料          | 按微信后台当前要求完成适龄提示、游戏简介、截图、客服信息                                                       | 产品          |

### 2.2.2 第一款建议用哪个产品跑通合规链路
建议使用B《清理大师》跑第一条平台合规链路。理由：题材安全、无明显暴力/宫斗/盗墓争议，游戏结构轻，适龄提示和内容审核更容易解释，同时其IAA商业化逻辑最清晰。A和C等第一条链路稳定后再注册并复制。

## 2.3 域名、服务器、备案和隐私
### 2.3.1 域名与云资源
- 域名尽量以公司名义购买和实名认证，避免以后主体迁移。

- 首款MVP优先选择中国内地云厂商/微信云开发等，降低网络接入和备案协同复杂度。

- 服务端只做必要功能：登录映射、远程配置、埋点接收/转发、云存档（正式发布必需）。能不用自建账号体系就不自建。

- 强制HTTPS；密钥、AppSecret只放服务端/密钥管理，不写入客户端包。

### 2.3.2 APP/小程序备案
工信部明确要求，在中国境内从事互联网信息服务的APP主办者履行备案手续，分发平台范围包含小程序、快应用等。备案由网络接入服务提供者或分发平台协助提交至属地通信管理局；材料齐全准确的，省级通信管理局原则上在20个工作日内完成备案。[R4]

| **准备材料** | **你的操作**                                                                              |
|--------------|-------------------------------------------------------------------------------------------|
| 企业主体信息 | 营业执照、统一社会信用代码、公司住所、通信地址等保持一致                                  |
| 负责人信息   | 法人/主体负责人及小游戏负责人身份证、手机号、邮箱、应急联系方式；按平台要求完成电子化核验 |
| 应用信息     | 小游戏名称、AppID、服务内容、域名/IP/接入信息、类目                                       |
| 前置审批说明 | 如页面提示出版等前置审批材料，按当前IAA路径和属地要求提交；不要自行“跳过”                 |
| 备案号展示   | 取得备案号后按平台/工信要求在显著位置展示或由分发平台展示                                 |

### 2.3.3 隐私最小化策略
首款MVP应尽可能设计成“没有手机号、没有地址、没有通讯录、没有相册权限也能玩”。只要能用微信平台身份标识完成会话和数据统计，就不要额外收集个人信息。用户协议、隐私政策、第三方SDK清单、数据用途、保存期限、删除/注销渠道需与实际代码一致。

## 2.4 第一阶段IAA上线合规：最实用的操作路径
> **重要边界**
>
> 法律层面，《未成年人保护法》规定网络游戏经依法审批后方可运营；国家新闻出版署的传统国产网络游戏审批路径要求运营机构具备ICP证。[R3][R6] 同时，微信平台目前对无内购IAA小游戏存在独立的资质审核/备案/发布路径。实际执行时，不能把“平台允许走IAA流程”简单理解为法律层面的通用版号豁免。首款提审时，应以微信后台给出的资质项及属地新闻出版要求为准，并保留未来转传统版号路径的材料一致性。

### 2.4.1 首款IAA需要准备的“资料包”
| **资料**            | **建议完成时间** | **实操说明**                                                                        |
|---------------------|------------------|-------------------------------------------------------------------------------------|
| 营业执照/主体资料   | 立即             | 扫描件和电子证照都准备，名称地址一致                                                |
| 游戏名称/Logo/简介  | W1               | 先查重和商标风险，不要用知名IP近似名                                                |
| 玩法说明+截图/录屏  | W2–W3            | 说明核心玩法、广告点、用户流程                                                      |
| 软件著作权/权属证明 | 开发同步启动     | 软著申请材料包括申请表、程序/文档鉴别材料和主体证明；未来版号名称尽量保持一致[R9] |
| 游戏自审自查材料    | 提审前           | 内容、文本、图片、广告点、未成年人、概率/抽奖等逐项自查                             |
| 隐私政策/用户协议   | W2               | 与实际数据收集完全一致                                                              |
| 适龄提示            | 提审前           | 根据玩法与内容完成分类提示                                                          |
| 备案材料            | 版本测试阶段并行 | 按微信后台与属地通管局要求提交                                                      |
| 客服与投诉渠道      | 提审前           | 公司可控邮箱/客服入口，避免个人临时联系方式                                         |

### 2.4.2 未成年人和实名防沉迷
网络游戏企业必须落实实名注册和防沉迷要求。现行国家新闻出版署规则要求，未成年人仅可在周五、周六、周日和法定节假日20:00–21:00获得1小时网络游戏服务，并要求网络游戏接入实名验证体系，不得向未实名用户提供游戏服务。[R5] 《未成年人网络保护条例》还要求适龄提示、消费管理等措施。[R6]

技术实施上，不要自己在客户端做“年龄判断”。首版架构应预留服务端身份校验、未成年人状态、可玩时段/剩余时长和支付权限的统一控制层；具体优先使用微信平台当前提供的实名/防沉迷能力或其指定接入方式。

### 2.4.3 广告合规
- 不把看广告伪装成系统按钮；广告和游戏操作边界清晰。

- 不做强制分享、误导点击、虚假关闭按钮、诱导未成年人消费。

- 激励广告的奖励内容在播放前明确写清楚；播放失败要有兜底，不扣用户已有资源。

- B线“解压/清理”不要使用“治疗焦虑、预防老年痴呆”等医疗功效宣传。

- C线广告剧情可以夸张，但必须与游戏真实存在的剧情/玩法基本一致，避免严重货不对板。

## 2.5 Winner出现后：IAP、经营性ICP和版号实操路线
当某款产品已经通过IAA验证出较好D1/D7、激励广告转化和可接受CAC，再进入第二阶段。此时才值得投入内购和传统网络游戏出版审批。

### 2.5.1 先判断你的公司是否满足ICP许可基本条件
| **条件**       | **官方口径/实操**                                                       | **你的动作**                                              |
|----------------|-------------------------------------------------------------------------|-----------------------------------------------------------|
| 公司主体       | 依法设立的公司                                                          | 现有公司可满足                                            |
| 注册资本       | 省内经营通常最低100万元人民币，且不涉及外资等条件需按许可规则核验[R7] | 不足100万时再做合理增资；同步评估5年实缴义务              |
| 人员与能力     | 需要与业务相适应的资金、专业人员、长期服务能力                          | 准备技术/安全/客服岗位和制度                              |
| 场地/设施/方案 | 业务发展计划、技术方案、网络与信息安全制度                              | 可由公司自己准备，必要时咨询专业代理                      |
| 经营范围       | 许可项目需与实际许可匹配                                                | 变更“互联网信息服务/第二类增值电信业务”等后，再申请许可证 |

### 2.5.2 经营性ICP实际办理顺序
1.  确认公司注册地通信管理局的最新申请口径。

2.  确认注册资本、股权、人员和域名/APP备案信息满足要求。

3.  在工信部电信业务市场综合管理信息系统提交增值电信业务经营许可申请。

4.  准备业务发展计划、技术方案、用户信息安全制度、网络安全制度、应急方案等材料。

5.  取得许可证后，确保实际业务、域名/应用和许可证载明信息一致，变更时及时办变更。

### 2.5.3 版号路线
国家新闻出版署当前国产网络游戏审批的硬条件包括：出版单位须具有网络游戏出版范围；著作权人须为中国公民或内资企业；运营机构须具有ICP证；游戏须符合内容和未成年人保护等要求。[R3]

| **步骤**                        | **你需要做什么**                                                                             |
|---------------------------------|----------------------------------------------------------------------------------------------|
| 1\. 权属锁定                    | 游戏代码、美术、文本权利归公司；软著/自我声明/公证等权属材料准备                             |
| 2\. 选择出版单位                | 寻找具有网络游戏出版范围的网络出版服务单位合作，不自己申请“网络出版服务许可证”               |
| 3\. 完成ICP                     | 你的公司如果作为运营机构，需要有效ICP证                                                      |
| 4\. 准备审查版本                | 游戏名称、内容、截图、脚本全文、屏蔽词库、管理账号、防沉迷说明等按申报清单准备               |
| 5\. 出版单位审读                | 按出版单位反馈修改内容并形成审读报告                                                         |
| 6\. 省级主管部门→国家新闻出版署 | 正式申报；官方服务指南载明受理后许可期限为80个工作日，不含前期出版审读、修改和排队时间[R3] |
| 7\. 获批后商业化                | 再开完整IAP/虚拟道具付费和规模投放                                                           |

> **批量小游戏的一个有利点**
>
> 国家新闻出版署的国产网络游戏审批说明明确：同一平台运行的小游戏10个以上，可以同一文件申报，原则上一次不超过20个。但这不等于多款游戏“共用一个版号”，只是申报文件可以批量组织。[R3]

## 2.6 财税、结算与合同
- 广告平台和微信结算账户使用公司主体；收入全部进入公司账户并由财务按平台结算单入账。

- 具体开票品目、增值税计税方式、小规模/一般纳税人处理以你公司的纳税人身份和实际合同为准，首款上线前让代账/财务确认一次即可。

- 所有外包和素材采购留合同、发票/付款凭证、交付清单，降低后续软著/版号权属核验风险。

- 投放账户建议公司主体开户，建立“产品-渠道-素材-批次”成本归因，避免个人微信支付散账。

## 2.7 技术基础架构
推荐一套Core Engine，A/B/C作为三个Product Package。技术选型优先考虑Cocos Creator + TypeScript或团队最熟悉的2D技术栈。关键不是追求引擎先进，而是做到一套代码能快速输出微信小游戏和手机H5。

| **层**     | **必须能力**                                                     | **V1不要做**             |
|------------|------------------------------------------------------------------|--------------------------|
| Core       | 配对判定、地图生成、死局、洗牌、提示、Timer开关、Combo、特殊棋子 | 复杂物理/3D              |

# 3. 营销管理
## 3.1 总原则：玩法越大众，传播越不能大众
“经典连连看、轻松解压”没有传播竞争力。营销必须把产品功能翻译成社会情绪或认知冲突，但避免低级争吵和虚假功效。每款产品立项时必须同时交付四个Hook：Product Hook、Emotion Hook、Content Hook、Discussion Hook。

| **Hook**        | **要回答的问题**       | **例子**                             |
|-----------------|------------------------|--------------------------------------|
| Product Hook    | 产品一句话哪里不一样？ | “一个不催你的连连看。”               |
| Emotion Hook    | 用户为什么在乎？       | “上班已经够赶了，玩游戏还催我？”     |
| Content Hook    | 15秒视频拍什么？       | 脏鸡圈被一层层清空，最后Before/After |
| Discussion Hook | 为什么会评论/转发？    | “我妈最讨厌倒计时”“谁懂周五17:59”    |

## 3.2 A线营销：打工人冲突
- 开头3秒：“周五17:59，老板说有个简单需求。”

- 游戏中疯狂清理PPT、Excel、邮件图标，Combo越高视觉越夸张。

- 结尾保留临界失败：“还差最后一对，只有5秒。”

- 素材评论区目标不是夸游戏画风，而是引发“太真实了”的工作情绪共鸣。

## 3.3 B线营销：可视化解压
- 前3秒必须先展示“很脏/很乱”的强视觉问题。

- 中段用连续配对让场景逐渐变干净，尽量少讲规则。

- 最后用Before/After完成闭环。

- 文案方向：“强迫症千万别点”“我把老王鸡圈收拾了半小时”“这个游戏不催你，只让你收拾。”

- B线可天然延展成短视频内容账号：真实清理视频/AI解压内容→游戏玩法→新场景征集。

## 3.4 C线营销：短剧/爽文逻辑
C线广告不卖“连连看”，而卖“下一集”。素材结构建议：3秒冲突→5秒身份反转→5秒游戏承接→2秒悬念。广告里的核心剧情必须在游戏中真实存在，避免严重货不对板。

| **秒数** | **内容**                       | **目的**   |
|----------|--------------------------------|------------|
| 0–3s     | 丈夫/合伙人背叛、酒楼被夺      | 制造冲突   |
| 3–8s     | “再睁眼，我回到了十年前”       | 身份反转   |
| 8–13s    | 连连看完成订单，酒楼从破败变好 | 证明可操作 |
| 13–15s   | 神秘NPC出现/前夫上门           | 留下悬念   |

## 3.5 素材赛马与预算
每款MVP首轮投放建议3,000–5,000元，不以“跑量”作为目标，只为了买到足够判断创意和产品漏斗的数据。每款至少准备10–20条差异明显的素材，不允许只剪一个视频反复改字幕。

| **层级** | **动作**                                        | **淘汰逻辑**                        |
|----------|-------------------------------------------------|-------------------------------------|
| 素材层   | 10–20条首发素材，测试不同冲突/首帧/标题/人群    | CTR和有效进入率明显低的素材快速停   |
| 产品层   | 保留来源creative_id，比较素材带来的D1和广告价值 | 高CTR低留存的“骗点击素材”不算Winner |
| 渠道层   | 比较不同渠道CAC、用户质量和回收                 | 只在LTV能够覆盖CAC的渠道扩量        |

## 3.6 营销价值回检
任何营销复盘不以“10万播放、1万点赞”为结论，必须回到一条完整价值链：花费 → 点击 → 有效新增 → D1/D7 → 广告/付费收入 → 预测LTV → ROI。内容团队和产品团队共用一张素材损益表。

# 4. 数据复盘与投资决策
## 4.1 三种结局
| **结局** | **定义**                                        | **动作**                                          |
|----------|-------------------------------------------------|---------------------------------------------------|
| Kill     | 两轮迭代后关键留存/变现仍低，或CAC远高于预测LTV | 停止投放、冻结开发，只保留可复用代码/素材方法     |
| Continue | 某些指标有明显亮点，但漏斗存在可解释问题        | 限定下一轮预算和目标，只解决1–2个最大问题         |
| Scale    | 单位经济模型出现正向或接近正向，且素材可复制    | 扩大素材、增加内容；此时才评估IAP、版号和更大投放 |

## 4.2 三款产品各自的主判断指标
| **产品** | **第一判断**                         | **第二判断**          | **不被表面数据误导**                     |
|----------|--------------------------------------|-----------------------|------------------------------------------|
| A        | 失败后激励广告转化、广告ARPDAU       | CAC、D1               | 高失败率若导致大量退出，不是好事         |
| B        | 平均Session、连续清理场景数、D1/D7   | 提示/工具广告主动率   | “玩得久”但广告价值为0也不可放大          |
| C        | 章节完成、复访、为了继续剧情付出成本 | 付费代理指标、预测LTV | 剧情点击高但用户不进入核心循环，不算成功 |
